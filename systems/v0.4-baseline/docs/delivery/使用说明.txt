AI换脸涉案图像智能鉴伪与原始素材溯源系统 v0.3.1
AIGC修复正式版
使用说明

1. 系统用途

本系统对单张图片提供三类辅助能力：AI换脸/深伪风险甄别、当前身份库内人员候选检索、当前底图库内素材候选检索。可以只运行一个模块，也可以一键运行三个模块。

本系统只提供侦查线索和辅助研判信息。任何分数或排名都不应单独作为案件定性、人物身份认定或图像来源认定的依据。

2. 安装方法

（1）先核对交付包中的“安装包SHA256.txt”，确认安装器文件名、大小和 SHA-256 一致。
（2）双击“换脸寻源系统_v0.3.1_Setup.exe”。
（3）按安装向导操作；可选择是否创建桌面快捷方式。默认安装在当前用户的本地应用目录，不要求管理员权限。
（4）安装完成后可直接启动。

安装后的主程序名为“换脸寻源系统_v0.3.1.exe”，桌面和开始菜单快捷方式名为“换脸寻源系统 v0.3.1”。v0.3.1 使用独立版本标识，不应与旧版快捷方式或日志混用。

正式安装与卸载已在中文和空格路径中完成真实验收：安装、启动、四类真实分析、报告导出、关闭、再次启动和卸载均通过；卸载后用户任务报告保留。

3. 启动方法

可从桌面快捷方式或开始菜单“换脸寻源系统 v0.3.1”启动。程序先检查真实模块和资源，再启动只监听本机的页面。首选端口为 8767；如果被占用，程序会自动选择可用端口。服务就绪后会自动打开默认浏览器。

如重复启动，程序只复用经核验的本安装实例，不会随意连接其他进程。正常退出请点击页面侧栏“关闭系统”，或使用开始菜单中的“停止换脸寻源系统 v0.3.1”。

4. 第一次启动的资源检查

第一次和以后每次启动都会检查：正式版本标记、三个真实模块、AIGC完整空间域checkpoint、频域模型、融合配置、判定阈值配置、Python解释器、torch、torchvision、sklearn、OpenCV、CUDA状态、InsightFace buffalo_l 五个模型文件、默认身份库、默认底图库、资源大小与 SHA-256 清单，以及用户数据目录是否可写。

本安装包已经随包提供AIGC完整空间域checkpoint（包含MobileNetV3-Small backbone与classifier全部参数）、频域模型和融合配置。正式推理以 mobilenet_v3_small(weights=None) 构造网络后严格加载项目完整checkpoint，不需要、也不携带官方 mobilenet_v3_small-047dcff4.pth 基础权重；运行时不会从用户Torch缓存或互联网下载该权重。

从页面侧栏执行AIGC启动前资源检查的方法：

（1）启动系统后，在侧栏“系统就绪状态”中展开“AIGC启动前资源检查”；系统进入页面时已自动执行一次检查。
（2）逐项查看空间域模型、频域模型、融合配置、判定阈值、Python、torch、torchvision、sklearn、OpenCV和CUDA状态。
（3）正常状态显示“AIGC模块：就绪”。资源缺失或异常时显示“AIGC模块：不可用”及具体资源名，并禁用真实AIGC分析。
（4）修复资源或重新安装后，点击侧栏“重新检测 / 重试服务”，即可清除缓存并重新执行检查。

检查失败时程序会列出缺失或不一致的资源并停止，不会使用模拟结果替代。详细日志位于：

%LOCALAPPDATA%\FaceSourceTrace\logs\launcher_v0.3.1.log

本安装包包含便携 Python 3.12 运行环境、真实AIGC运行程序及完整空间域checkpoint、频域模型、融合配置、InsightFace buffalo_l 五个 ONNX 模型、身份与底图检索程序、9 人/45 张参考图的示例身份库，以及 203 张图片的示例底图库，可离线运行三个真实模块。

正式交付的PyTorch为CPU版本，CPU环境可以独立完成真实AIGC推理。系统会把设备状态和模型加载状态分开显示：未检测到可用CUDA时自动使用CPU，这不是检测失败；如未来使用兼容CUDA运行时且GPU推理失败，系统会自动降级至CPU继续检测。最终以本次结果中的“实际运行设备”为准。

5. 如何选择或导入身份库

页面侧栏“本次任务身份库”默认使用安装时配置的正式身份库。要使用其他有权使用的身份库，可准备一个外部目录，并按以下方式组织：

身份库根目录\
  person_001\参考图1.jpg
  person_001\参考图2.jpg
  person_002\参考图1.jpg

每个人员使用独立子目录。把该根目录的完整路径填写到“本次任务身份库”。系统只读取参考图片，不应改写原图。图片必须可解码，并且每张用于建库的图片应恰好包含一张可检测人脸；无效图片会被记录或跳过。

不要把个人隐私图片、无权使用的图片或模拟测试图片导入正式库。

6. 如何选择或导入底图库

页面侧栏“本次任务底图库”默认使用安装时配置的正式底图库。要使用其他有权使用的图库，可把候选图片放到一个外部目录中，允许使用子目录，然后把根目录完整路径填写到“本次任务底图库”。

底图库至少要有一张可解码的支持格式图片。系统实时扫描图库，不修改原图。大图库运行时间较长属于正常情况。

7. 如何上传查询图片

在“案件图像分析”区域点击“上传涉案图片”，选择一张 JPG、JPEG、PNG 或 WEBP 图片，文件不能超过 20 MiB。页面显示预览后再选择分析按钮。

每次分析都会建立独立任务目录并保存查询副本。建议先按取证流程固定原始介质和哈希，再把工作副本交给系统分析。

8. 四种分析按钮分别有什么作用

“AI换脸/深伪风险甄别”：只计算空间域、频域和融合风险结果。

“人脸身份搜索”：检测查询图人脸，提取 512 维特征，在当前身份库中按人员平均余弦相似度返回候选。

“原始底图搜索”：屏蔽查询图主要人脸区域，完成全库粗检索和 SIFT/RANSAC 局部复核。

“一键综合分析”：依次运行三个模块，并列展示三类证据。三个模块的分数不会相加。

某一模块失败时其他已选择模块继续；任务可能显示 partial_success，并生成已有结果的部分报告。

9. 如何查看动态运行过程

分析开始后查看“实时分析流程”。页面显示总体状态、当前模块、当前步骤、已运行时间，以及三个模块的等待、运行中、完成、警告、失败或已跳过状态。

底图搜索会显示真实数量，例如“正在扫描底图库：73 / 203”和“正在几何复核：8 / 20”。点击“技术运行日志”可查看最近事件。页面约每 0.5 秒读取进度；为避免拖慢算法，事件不会在每张图片后强制刷新整个页面。

10. AIGC分数和阈值怎么理解

本模块使用 MobileNetV3-Small 空间域模型和 87 维频域统计 LogisticRegression。实际融合公式为：

融合风险分数 = 0.62 × 空间域分数 + 0.38 × 频域分数

当前图片阈值约为 0.36360106194654707，最终应以本次结果中显示的阈值为准。融合分数高于或等于阈值时提示深伪风险，低于阈值时表示本模型本次未检出明显深伪风险。

风险分数不是系统准确率，也不是司法结论。当前没有经独立验证的决策边界带，系统只显示实际阈值差值。无人脸或证据不足时可能不输出分数，也不强行给出真假判断。

“证据不足”或“无人脸”与“模型加载失败”不是同一含义：

（1）“未检测到有效人脸”表示输入已进入分析流程，但没有满足空间域分析要求的人脸；系统不输出真假结论。
（2）“证据不足”表示模型已加载，但本次有效证据不足以支持真假判断。
（3）“模型资源缺失”或“checkpoint解析失败”表示模型未能正常加载，属于系统资源/安装问题，不得解释成图片真实、风险较低或证据不足。

11. 人脸身份相似度怎么理解

系统要求查询图恰好检测到一张人脸，提取 512 维 L2 归一化特征，与身份库每张有效参考图计算余弦相似度。同一人员有多张参考图时，取这些相似度的平均值作为人员级分数。

页面同时显示最佳单张参考图分数、有效参考图数量、第二名分数和前两名差值。余弦相似度不是身份概率；第一候选只表示在当前身份库中排在最前，不能单独用于人物身份认定。系统默认未启用未经独立验证的开放集拒识阈值。

12. 底图全局分、局部分和最终分怎么理解

全局分来自颜色、灰度、边缘和外围区域等全局特征，用于全库粗排。

局部分来自 SIFT 特征、Lowe 比率检验和 RANSAC 几何验证。正常公式为：

局部分 = 0.6 × RANSAC内点率 + 0.4 × min(RANSAC内点数 / 40, 1)

有效匹配不足 4 个时，系统沿用基线公式：

局部分 = min(有效匹配数 / 40, 0.15)

最终分 = 0.45 × 全局分 + 0.55 × 局部分

页面还显示有效匹配点、RANSAC 内点、内点率、屏蔽查询图和匹配连线图。这些分数只是当前底图库的候选排序值，不是来源概率。

13. 如何导出检测结果

任务结束后页面显示“检测与检索结果已生成”。可以：

（1）点击“查看完整报告”在页面中预览；
（2）点击“导出TXT报告”；
（3）点击“导出HTML报告”；
（4）展开“报告技术详情”，导出 JSON 报告并查看任务结果目录。

HTML 可在浏览器中打开或打印。TXT、HTML 和 JSON 来自同一份结构化结果，均由本地确定性模板生成，不调用外部语言模型。

14. 结果文件保存在哪里

正式安装版默认保存到：

%LOCALAPPDATA%\FaceSourceTrace\tasks\case_任务编号\

其中包括 query.jpg、三个模块结果 JSON、unified_result.json、task_status.json、final_report.json、检测结果 TXT/HTML、visualizations 可视化目录和 logs 日志目录。

页面普通区域主要显示任务号和文件名；完整路径只放在技术详情。需要长期保留时，请备份整个 case 目录。

15. 常见问题和处理办法

启动提示资源缺失或哈希不一致：不要绕过检查，也不要改用模拟数据。先在侧栏展开“AIGC启动前资源检查”确认具体项目，再重新安装完整的v0.3.1正式包或联系维护人员；查看 launcher_v0.3.1.log。

提示“空间域模型资源缺失”：说明随包模型文件丢失或安装不完整。请重新安装完整模型资源，不要手工放入用户Torch缓存；正式版不需要官方MobileNet基础权重。

提示“空间域模型加载失败：模型文件存在，但checkpoint解析失败”：说明文件存在但无法解析、损坏或版本不兼容。保留技术日志，重新核验安装器SHA-256并重新安装，不要把它解释为“证据不足”。

显示“CUDA不可用，将使用CPU”或“GPU推理失败，已自动降级至CPU继续检测”：这是设备选择/降级提示。只要模型状态正常且任务继续完成，就不属于模型加载失败。正式交付本身使用CPU版PyTorch。

提示“输入图片无法读取或格式不支持”：重新导出受支持且可解码的工作副本，并保留原始文件及哈希；不要通过修改模型资源处理输入错误。

提示“未检测到有效人脸”：换用人脸清晰、尺度合适的图片；该状态不等于模型加载失败，也不能据此判断图片真假。

浏览器没有自动打开：稍候片刻后再次点击程序快捷方式。启动器会打开当前真实服务地址；不要固定猜测端口。

分析按钮不可用：查看顶部和侧栏的系统状态，确认上传格式、默认模型、身份库和底图库可用；点击“重新检测 / 重试服务”。

首次启动身份库仍在初始化：本机首次为 45 张参考图建立有效 embedding 缓存约需数分钟。等待完成后点击一次“重新检测 / 重试服务”即可刷新页面状态；以后启动可复用缓存。

身份搜索提示无人脸或多人脸：换用人脸清晰、仅含一张主要人脸的工作副本，不要把错误状态解释成低相似度结果。

底图搜索时间较长：本模块需要实时扫描全库并复核候选，默认超时为 600 秒。观察真实扫描数量，不要重复启动多个任务争用资源。

报告暂不可用：先查看任务状态和 logs。即使报告生成失败，三个原始模块 JSON 仍应分别复核。

需要停止程序：优先点击页面“关闭系统”，也可使用开始菜单中的停止快捷方式。卸载前先关闭程序并备份需要的任务目录。

16. 边界说明

正式安装版默认运行真实模块，Mock 入口关闭。开发模拟数据不能作为模型、准确率或案件证据。

三个模块处理不同问题，风险分数、身份余弦相似度和底图检索分数不能相加，也不能转换成跨模块概率。

本系统用于深度伪造风险筛查、身份候选检索和底图候选检索，仅提供侦查线索和辅助研判信息，不替代原始介质固定、哈希校验、人工复核或司法鉴定。
