# v0.3 模型、算法与运行环境说明

本文记录 v0.3 实际模型、公式、诊断字段和正式运行边界。它不是效果承诺；所有分数只能在各自模块中解释。

## 1. AI换脸/深伪风险甄别

### 模型与输入流程

- 空间域模型：MobileNetV3-Small 二分类网络，类别定义为 `REAL=0`、`FAKE=1`。
- 频域模型：87 维 FFT、DCT、噪声与统计特征，经过 `StandardScaler + LogisticRegression`。
- 单图预处理：OpenCV 解码、Haar 人脸检测、选择主要人脸并扩展约 25%、缩放至 224×224。
- 当前统一入口只支持单张图片；不据安装资源中的视频参数声称本版本支持视频。

### 分数和阈值

```text
fusion_score = 0.62 × spatial_score + 0.38 × frequency_score
```

当前图片阈值为：

```text
0.36360106194654707
```

融合分数高于或等于阈值时形成深伪风险提示，低于阈值时形成未检出明显风险的结果。复核时以本次 `detection_result.json` 中的真实权重、分数和阈值为准，不从标签反推原因。

当前没有经独立验证的决策边界带，因此配置 `boundary_notice.enabled=false`。页面只显示实际阈值差值，不声称高置信或低置信。无人脸或没有有效帧时返回 `insufficient_evidence`，不输出虚构分数。

## 2. 人脸身份搜索

### 模型和特征

- 模型包：InsightFace `buffalo_l`，正式模型清单恰好包含五个已批准 ONNX 文件。
- 推理接口：`insightface.app.FaceAnalysis`。
- 检测尺寸：1280×1280。
- 查询要求：必须恰好检测到一张人脸；无人脸和多人脸均返回结构化错误。
- 特征：512 维 float32 embedding，检索前执行 L2 归一化。

### 排序算法

查询向量与每张有效参考图计算余弦相似度。同一人员有多张参考图时，对该人员的所有有效相似度取算术均值；按人员均值降序排序，身份 ID 用作稳定并列排序键。v0.3 补充逐参考图相似度、最佳单图分数和路径，但不改变人员均值及排名逻辑。

结果记录查询人脸框和检测分、特征维度、身份库人数、参考图片数、有效 embedding 数、缓存状态、候选参考图数量、人员均值、最佳参考图、前两名差值、模型和库指纹。

系统没有经独立验证的开放集拒识阈值，正式配置 `open_set_rejection_enabled=false`。余弦相似度不是身份概率；结果只提供当前身份库内候选线索。

### 缓存与运行设备

身份缓存为带图库/模型/预处理指纹的 JSON+NPZ，验证 schema、文件 SHA-256、顺序、shape、dtype 和有限值。正式安装版缓存写入：

```text
%LOCALAPPDATA%\FaceSourceTrace\cache\identity
```

当前真实回归环境使用 CPUExecutionProvider。正式安装配置固定 CPU；不得因机器存在独立显卡而把未实际使用的设备写成 GPU。

## 3. 原始底图搜索

该模块没有训练模型、FAISS 或数据库服务。冻结算法为：

1. Haar 检测查询图主要人脸并生成屏蔽掩膜；未检测到人脸时使用完整图像。
2. 提取 HSV、灰度、边缘、缩略图和外围区域等全局特征。
3. 对底图库逐图解码和计算全局相似度，按全局分粗排。
4. 选取 `min(max(top_k × 4, 20), 可用候选数)`；默认 Top-K=5 时通常复核 Top-20。
5. SIFT `nfeatures=2500`、BFMatcher L2、Lowe ratio=`0.75`。
6. 有效匹配不少于 4 个时，以 RANSAC 阈值 `5.0` 执行几何验证。

正常局部分：

```text
local_score = 0.6 × ransac_inlier_ratio
            + 0.4 × min(ransac_inlier_count / 40, 1)
```

有效匹配不足 4 个时沿用 v0.2 基线分支：

```text
local_score = min(good_match_count / 40, 0.15)
```

最终分：

```text
final_score = 0.45 × global_score + 0.55 × local_score
```

v0.3 保存屏蔽查询图、图库解码/跳过数量、shortlist 数、查询与候选关键点数、有效匹配数、RANSAC 是否执行/成功、内点数、内点率、局部分量、权重、前两名差值和匹配可视化。粗检索与几何复核事件使用实际处理数量。

底图分数是当前库内的检索排序值，不是图像来源概率。该模块仍实时扫描，没有持久化特征索引；正式默认超时为 600 秒。

## 4. v0.3 真实算法回归

对 `integrated_query_001.jpg` 的 v0.2/v0.3 对比结果：

- AIGC 空间分、频域分、融合分、阈值和分类完全一致；容差 `1e-9`。
- 身份 Top-5 人员顺序完全一致，最大绝对分数差约 `1.9531e-05`，小于 `0.0001` 容差；另一次同环境直接模块回归的 Top-5 分数差为 0。
- 底图 Top-5 文件顺序一致，全局分、局部分和最终分差均为 0；容差 `1e-6`。

真实 v0.3 三模块还覆盖 `integrated_query_002.jpg` 和 `integrated_query_003.jpg`；AIGC 边界样例覆盖高于阈值、低于阈值和无人脸证据不足。证据在 `docs/regression_test_results/`。

这些测试证明当前资源和样例上的工程回归，不代表现实案件总体准确率。

## 5. 正式安装资源与隔离

正式配置不使用开发机绝对路径：

- AIGC：安装目录内受控便携 Python、真实深伪运行资源和基础权重。
- 身份：安装目录内独立 `identity_worker.exe`、`buffalo_l` 模型和默认身份库。
- 底图：安装目录内独立 `source_search.exe` 和默认底图库。
- 用户写入：`%LOCALAPPDATA%\FaceSourceTrace`。

启动器要求正式构建标记、真实模块默认开启、Mock 关闭、资源清单校验开启，并校验所列文件的大小和 SHA-256。无法确认分发授权的资源不得装入最终包；最终安装包实际包含哪些模型和数据库：`【待最终验收回填】`。

安装、启动、真实三模块、综合分析、报告导出、重启和卸载验收：`【待最终验收回填】`。
