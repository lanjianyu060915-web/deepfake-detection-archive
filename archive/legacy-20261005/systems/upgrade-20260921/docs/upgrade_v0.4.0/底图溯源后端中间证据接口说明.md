# 底图溯源后端中间证据接口说明

## 1. 兼容性约定

本次只增加可观测旁路，不改变底图检索算法。`source_result.json` 原有的
`status`、`query_image`、`candidates`、`runtime_seconds`、`method`、
`metrics`、`explanation`、`warnings`、`limitations`、`provenance` 和
`diagnostics` 均保留。候选中的 `rank`、`file_path`、`global_score`、
`local_score`、`final_score`、`visualization_path` 及原有取整方式也保留。

新增的主要入口位于结果顶层：

```json
{
  "visual_evidence": {"source": {}},
  "artifact_manifest": []
}
```

同一结构也镜像在 `diagnostics.visual_evidence` 和
`diagnostics.artifact_manifest`，便于旧版只读取 diagnostics 的调用方平滑升级。

## 2. `visual_evidence.source`

### 2.1 `query`

- `original_image`：查询图在任务目录内时的相对路径；外部直接调用时为 `null`。
- `face_detection_image`：真实检测框及实际屏蔽轮廓图。
- `face_masked_image`：后端本次实际送入全局特征提取的 masked 查询图。
- `face_detected`、`face_bbox`、`face_mask_applied`、`masked_pixel_count`：真实检测与掩膜统计。
- `mask_purpose`：屏蔽人脸是为了降低换脸区域对场景检索的干扰；未检测到人脸时使用完整图像。

### 2.2 `global_stage`

该块是全库漏斗的真实计数：

- `library_file_count`：扫描到的受支持候选图片数；
- `library_decoded`：成功解码数；
- `library_skipped_count` / `library_skipped_paths`：失败数及路径；
- `global_compared_count`：实际完成全局比较的图片数；
- `shortlist_size`：进入 SIFT 局部复核的候选数；
- `returned_top_k`：最终返回数量。

### 2.3 `global_scoring`

现有全局分原本已经由四个真实通道形成，本次仅把中间量输出：

```text
0.30 × HSV直方图相关相似度
+ 0.25 × 灰度缩略图余弦相似度
+ 0.15 × 边缘图余弦相似度
+ 0.30 × 外围区域MAE相似度
```

每个 Top-K 候选在 `components` 中包含：

- `hsv_histogram_similarity`
- `grayscale_thumbnail_similarity`
- `edge_map_similarity`
- `border_region_similarity`
- `border_common_pixel_count`
- `weights`
- `weighted_terms`
- `formula`
- `score`

这些值来自原有 `global_similarity` 的同一运算，不是为了图表而拆分出的估算值。

### 2.4 `top_candidates`

Top-K 候选包含排名、文件名、任务内候选图、全局分、局部分、最终分、Lowe
有效匹配数、RANSAC 内点数/内点率、内点匹配图及相对第一名差值。候选仍只表示
“当前底图库内候选”，不是来源概率或来源确认。

### 2.5 `local_matching`

第一候选输出：

- 查询图和候选图 SIFT 关键点图；
- `matches_all`：全部通过 Lowe 0.75 比率检验的匹配；
- `matches_inliers`：旧版兼容的 RANSAC 内点匹配图；
- `matches_inliers_outliers`：绿色内点、红色外点；
- `homography_overlay`：单应矩阵存在且投影数值稳定时生成；
- 查询/候选关键点数、KNN 对数、Lowe 匹配数、内点/外点数；
- `homography_matrix`：本次 `cv2.findHomography` 的真实矩阵或 `null`。

不足 4 个 Lowe 匹配时不执行 RANSAC，字段会如实标记；不会伪造投影图。

### 2.6 `fusion`

该块输出未取整的真实全局分、局部分、两项权重、两项贡献、最终分、第二候选
最终分及 Top1-Top2 差值。原有公式保持：

```text
final_score = 0.45 × global_score + 0.55 × local_score
```

局部分的原有计算也未改变：

```text
0.6 × RANSAC内点率 + 0.4 × min(RANSAC内点数 / 40, 1)
```

不足 4 个 Lowe 匹配时仍使用原有 `min(good_match_count / 40, 0.15)`。

## 3. `artifact_manifest`

每项固定包含：

```json
{
  "id": "source_top1_matches_all_lowe",
  "kind": "source_lowe_matches_all",
  "path": "visualizations/source/source_result_<hash>_top1_matches_all_lowe.jpg",
  "sha256": "...",
  "size_bytes": 123,
  "status": "success",
  "description": "..."
}
```

所有生成文件均使用任务目录相对、POSIX 风格路径。证据文件名带输入哈希前缀；
`sha256` 和 `size_bytes` 在文件写入成功后计算。单应投影无法稳定生成时，manifest
仍保留对应条目，但 `path`/`sha256` 为 `null`、`size_bytes` 为 0、状态为
`not_generated`，前端应显示“本次任务未生成该证据”。

## 4. 真实进度阶段

source worker 现在在实际代码执行点发布以下阶段：

1. `validate_source_input`
2. `read_source_query`
3. `detect_source_query_face`
4. `mask_query_face`
5. `extract_query_global_features`
6. `decode_source_library`
7. `scan_source_library`
8. `source_global_ranking`
9. `source_geometric_review`
10. `source_sift_features`
11. `source_lowe_filter`
12. `source_ransac_verification`
13. `source_score_fusion`
14. `source_final_ranking`
15. `generate_source_visual_evidence`
16. `source_search_complete`

全库扫描和候选复核的百分比只由真实完成数量计算。SIFT、Lowe、RANSAC 等子阶段
使用候选序号和真实统计，不分配虚构的百分比，也未增加固定 sleep。
