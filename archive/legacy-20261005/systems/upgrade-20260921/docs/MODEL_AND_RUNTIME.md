# v0.3 模型、算法与运行环境说明

本文记录 v0.3 实际模型、公式、诊断字段和正式运行边界。它不是效果承诺；所有分数只能在各自模块中解释。

## 1. AI换脸/深伪风险甄别

### 模型与输入流程

- 空间域模型：MobileNetV3-Small 二分类网络，类别定义为 `REAL=0`、`FAKE=1`。
- 频域模型：87 维 FFT、DCT、噪声与统计特征，经过 `StandardScaler + LogisticRegression`。
- 单图预处理：OpenCV 解码、Haar 人脸检测、选择主要人脸并扩展约 25%、缩放至 224×224。
- 当前统一入口只支持单张图片；不据安装资源中的视频参数声称本版本支持视频。

### 分数和阈值

```text
fusion_score = 0.62 × spatial_score + 0.38 × frequency_score
```

当前图片阈值为：

```text
0.36360106194654707
```

融合分数高于或等于阈值时形成深伪风险提示，低于阈值时形成未检出明显风险的结果。复核时以本次 `detection_result.json` 中的真实权重、分数和阈值为准，不从标签反推原因。

当前没有经独立验证的决策边界带，因此配置 `boundary_notice.enabled=false`。页面只显示实际阈值差值，不声称高置信或低置信。无人脸或没有有效帧时返回 `insufficient_evidence`，不输出虚构分数。

**升级说明（M3，2026-09-20）**：上一段描述的是 v0.4.0 冻结融合分支。
升级版新增二代整图分支（`CommunityForensics-DeepfakeDet-ViT`，ONNX），它**不沿用**这里的固定融合权重，
而按输入有效短边路由：短边 ≥ 256 px 走二代整图分支，否则走上面的冻结人脸裁剪分支。
二代分支有自己经独立校准集标定的分带（`low_max` / `medium_max`，见
`packaging_v0.4/resources/detectors_v2/communityforensics_vit/calibration.json`），
SWAN-DF 留出集（案例 11–20）AUC 0.9925。
**该分支的有效性依赖输入质量**（M3.1 鲁棒性评测，11 种退化 × 100 张）：JPEG q95 与原图逐字一致，
缩小到一半 0.9950，但 0.25 倍重采样后掉到 0.6400、翻拍近似 0.7675、二次编码近似 0.8175；
重采样还会让真人分数整体上移 300~400 倍，使冻结分带失效（真人误报率 0.56、提示精确率 0.24）。
详见 `D:\刑科技项目升级2.0\docs\M3_检测器鲁棒性评测.md`。

## 2. 人脸身份搜索

### 模型和特征

- 模型包：InsightFace `buffalo_l`，正式模型清单恰好包含五个已批准 ONNX 文件。
- 推理接口：`insightface.app.FaceAnalysis`。
- 检测尺寸：冻结 worker 固定 1280×1280。

  **升级说明（M2，2026-09-20）**：`config.json` 的 `identity` 段已切到
  `modules/identity_search_v2`（`python` + `runner` + `persistent_worker`，不再使用冻结 exe）。
  查询侧按检测尺度链 `1280 → 640 → 320` 回退：只有某一档「一个人脸都检不到」时才试下一档，
  多人脸、解码失败等其他错误立即上抛，保持冻结的单脸契约。库索引仍固定用第一档 1280 构建，
  缓存指纹与冻结版一致，**不需要重建索引**。
  结果 JSON 在 `method.preprocessing` 与 `metrics` 中记录尺度链、实际生效尺度、是否回退与逐档尝试；
  常驻 worker 的 `health.details` 暴露 `worker=identity_v2`、`detection_policy` 与 `det_size_chain`。
  实测：冻结 1280 档在 20 例 720×1280 竖屏换脸帧上漏检 10 例，回退后 20/20 可判定，库内 10/10 分数无退化。
  详见 `D:\刑科技项目升级2.0\docs\M2_人脸预处理_尺度回退实验.md`。
- 查询要求：必须恰好检测到一张人脸；无人脸和多人脸均返回结构化错误。
- 特征：512 维 float32 embedding，检索前执行 L2 归一化。

### 排序算法

查询向量与每张有效参考图计算余弦相似度。同一人员有多张参考图时，对该人员的所有有效相似度取算术均值；按人员均值降序排序，身份 ID 用作稳定并列排序键。v0.3 补充逐参考图相似度、最佳单图分数和路径，但不改变人员均值及排名逻辑。

结果记录查询人脸框和检测分、特征维度、身份库人数、参考图片数、有效 embedding 数、缓存状态、候选参考图数量、人员均值、最佳参考图、前两名差值、模型和库指纹。

系统没有经独立验证的开放集拒识阈值，正式配置 `open_set_rejection_enabled=false`。余弦相似度不是身份概率；结果只提供当前身份库内候选线索。

**升级说明（M1，2026-09-20）**：`open_set_rejection_enabled=false` 描述的是检索器本身不做拒识，事实不变；
升级版在其上层新增 `decision/` 判定层，阈值来自独立校准集并写入
`packaging_v0.4/resources/decision/open_set_thresholds.json`（`config.json` 的 `decision` 段声明同一路径）。
身份检索的判据为 Top-1 人员均值余弦（拒识 0.2229 / 高可信 0.4698）与 Top1-Top2 间隔（最低 0.1874）；
底图检索的判据为 `global_score`（拒识 0.6409 / 高可信 0.8748），
`local_score` 与 RANSAC 内点在库外样本上同样会偏高，只作证据强度描述。详见 `docs/M1_开放集三态与证据质量层.md`。

### 缓存与运行设备

身份缓存为带图库/模型/预处理指纹的 JSON+NPZ，验证 schema、文件 SHA-256、顺序、shape、dtype 和有限值。正式安装版缓存写入：

```text
%LOCALAPPDATA%\FaceSourceTrace\cache\identity
```

当前真实回归环境使用 CPUExecutionProvider。正式安装配置固定 CPU；不得因机器存在独立显卡而把未实际使用的设备写成 GPU。

## 3. 原始底图搜索

该模块没有训练模型、FAISS 或数据库服务。冻结算法为：

1. Haar 检测查询图主要人脸并生成屏蔽掩膜；未检测到人脸时使用完整图像。
2. 提取 HSV、灰度、边缘、缩略图和外围区域等全局特征。
3. 对底图库逐图解码和计算全局相似度，按全局分粗排。
4. 选取 `min(max(top_k × 4, 20), 可用候选数)`；默认 Top-K=5 时通常复核 Top-20。
5. SIFT `nfeatures=2500`、BFMatcher L2、Lowe ratio=`0.75`。
6. 有效匹配不少于 4 个时，以 RANSAC 阈值 `5.0` 执行几何验证。

正常局部分：

```text
local_score = 0.6 × ransac_inlier_ratio
            + 0.4 × min(ransac_inlier_count / 40, 1)
```

有效匹配不足 4 个时沿用 v0.2 基线分支：

```text
local_score = min(good_match_count / 40, 0.15)
```

最终分：

```text
final_score = 0.45 × global_score + 0.55 × local_score
```

v0.3 保存屏蔽查询图、图库解码/跳过数量、shortlist 数、查询与候选关键点数、有效匹配数、RANSAC 是否执行/成功、内点数、内点率、局部分量、权重、前两名差值和匹配可视化。粗检索与几何复核事件使用实际处理数量。

底图分数是当前库内的检索排序值，不是图像来源概率。该模块仍实时扫描，没有持久化特征索引；正式默认超时为 600 秒。

对 `integrated_query_001.jpg` 的 v0.2/v0.3 对比结果：

- AIGC 空间分、频域分、融合分、阈值和分类完全一致；容差 `1e-9`。
- 身份 Top-5 人员顺序完全一致，最大绝对分数差约 `1.9531e-05`，小于 `0.0001` 容差；另一次同环境直接模块回归的 Top-5 分数差为 0。
- 底图 Top-5 文件顺序一致，全局分、局部分和最终分差均为 0；容差 `1e-6`。

真实 v0.3 三模块还覆盖 `integrated_query_002.jpg` 和 `integrated_query_003.jpg`；AIGC 边界样例覆盖高于阈值、低于阈值和无人脸证据不足。证据在 `docs/regression_test_results/`。

这些测试证明当前资源和样例上的工程回归，不代表现实案件总体准确率。

## 6. 视频入口（2.0 升级层 M4）

视频任务沿用同一套模块与 schema 3.0 结果契约，差别在于输入的预处理与聚合层：

1. **抽帧与关键帧选择**（`modules/video_frames_v2/run_video_frames_v2.py`，开发解释器 + OpenCV + InsightFace）：
   在去掉首尾各 5% 的时间轴上均匀取 24 个候选帧（确定性，无随机数），逐帧测清晰度（Laplacian 方差）、
   亮度与人脸数，按 `0.55 × 人脸项 + 0.30 × 清晰度比 + 0.15 × 亮度项` 打质量分，再按
   「单人脸帧优先 → 质量分降序 → 已选帧之间保持最小时间间隔」贪心选出最多 5 帧，
   输出 JPEG（quality 95）与 `frame_selection.json`（含候选帧逐帧指标与选帧理由）。
2. **逐帧运行**：鉴伪 4 帧、身份 3 帧、底图 1 帧（首要帧），帧级结果写入
   `frame_results/<module>/frame_00N.json`；单帧失败只记为该帧失败，不终止整个视频任务。
3. **视频级聚合**（`video_pipeline/aggregate.py`）：
   - 鉴伪：帧级分数取**中位数**；视频级分带按帧级分带多数一致性规则（`band_majority`）。
     每一帧都公开 `band_source`：`calibrated_band`（二代内核的校准分带）或 `frozen_threshold`
     （冻结内核没有分带，只能按冻结阈值给出二值判定），混用时 `band_rule` 记为 `mixed`。
   - 身份：按人员聚合，取该人员在所有有脸帧上的**平均余弦相似度**排序，公开支持帧数与逐帧分数；
     参考图级字段取自得分最高的那一帧。
   - 底图：只检索首要帧——CPU 上逐帧检索昂贵，而同源相邻帧近乎同图。
4. **前端**：支持 `MP4/MOV/AVI/MKV` 上传（≤ 200 MiB）、视频预览、关键帧时间轴、
   视频级模块输出表与逐帧鉴伪明细。

视频输入的证据强度弱于单图：M3.1 实测「二次编码近似」会把留出集 AUC 降到 0.8175，
关键帧本身也是有损抽样。视频级分带规则**未使用独立视频校准集标定**，只能视为筛查口径，
不能当作准确率或鉴定结论。
