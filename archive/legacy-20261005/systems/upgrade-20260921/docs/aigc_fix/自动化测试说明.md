# AIGC 模型资源修复自动化测试说明

## 覆盖范围

`tests/test_aigc_model_resource_contract.py` 固化本次修复的关键契约：

1. 正式 `deepfake` 配置不含 `base_weight`、`torch_home`、Torch 用户缓存路径或开发机个人绝对路径。
2. 正式资源校验只要求项目完整空间域 checkpoint、频域模型、融合配置及其配套元数据，不要求官方 MobileNetV3-Small ImageNet 权重。
3. 模型资源缺失、checkpoint 解析失败、输入图片损坏、未检测到有效人脸分别映射到独立错误码和面向用户的准确提示。
4. CUDA 不可用或 GPU 失败后成功降级 CPU 时，检测仍为成功；设备状态与模型加载状态分开报告。
5. `system_status.inspect_system_status()` 在推理前公开 AIGC `components` 和 `readiness`，覆盖空间域模型、频域模型、融合配置、阈值、Python、torch、torchvision、sklearn、OpenCV 和 CUDA。
6. 正式空间域加载器必须用 `mobilenet_v3_small(weights=None)` 构造模型，并以 `strict=True` 加载项目 checkpoint。
7. 真实 checkpoint 的 `state_dict` 同时包含 `features.*` 与 `classifier.*`，与模型结构不存在 missing/unexpected keys；加载期间不创建或读取官方权重缓存。

## 运行方法

在修复版根目录运行轻量与正式资源契约测试：

```powershell
D:\刑侦查竞赛\first_week\_round1_work\backend\envs\A_env\Scripts\python.exe -B -m pytest tests\test_aigc_model_resource_contract.py -q
```

运行全量后端回归：

```powershell
D:\刑侦查竞赛\first_week\_round1_work\backend\envs\A_env\Scripts\python.exe -B -m pytest tests -q
```

正式 checkpoint 完整性测试会在隔离子进程中使用随 AIGC 运行时交付的 PyTorch/torchvision，仅加载一次约 6 MB 的 checkpoint，不执行训练、不修改参数、融合权重或判定阈值，也不会联网下载模型。

## 判定原则

- “模型资源缺失”或“checkpoint 解析失败”属于模型加载失败，不得归类为 GPU 故障或“证据不足”。
- “无人脸”是输入证据边界：模块可受控结束，但不得输出真假结论或伪造风险分数。
- CUDA 是可选加速能力；完整 CPU 运行时必须报告 AIGC `ready`。
- 任何重新引入 `mobilenet_v3_small-047dcff4.pth`、用户 Torch 缓存或开发机个人路径的变更都应使测试失败。
