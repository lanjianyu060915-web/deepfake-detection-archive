# AIGC 音视频伪造识别赛实施方案

状态：执行中
更新日期：2026-10-09

## 1. 目标与比赛约束

项目同时参加音频和视频两个项目。目标是在安全屋中离线运行两条批量检测流水线，
为每条媒体输出连续伪造分数，并以 EER 选择模型。

当前公开信息为：音频、视频各约一万条，真实与生成各约一半；两项均以 EER 计分；
每项目采用 2-1-2-1 的六日安全屋流程，最多提交三份结果及对应代码、参数。用户已报名，
官方没有提供更多执行资料。官方 I/O、硬件、资源限制、分数方向和外部资产规则未完整公布，
这些未知项集中保留在[比赛要求](../competition/requirements.md)，不再反复询问，也不阻塞本地实验。

本地统一约定：`real=0`、`fake=1`，分数越高越倾向伪造。官方接口公布后只修改适配层。

最终交付需要满足：

- 音频和视频分别有一个可离线运行的主模型，以及有实验证据时才保留的备选模型；
- 使用冻结配置在未参与调参的留出数据上评测；
- 每个输入都有分数或明确失败记录，不静默丢弃；
- 交付包包含代码、配置、权重、必要依赖和许可文件，在断网环境完成批量推理；
- 记录 EER、失败率、吞吐、耗时和峰值显存，不承诺未经实测的成绩或名次。

## 2. 当前基线与主要缺口

当前真实进度以[项目状态](../status.md)为准。已经完成小规模双分支实验：

- 语音：LogMel CNN 和 AASIST-L 各两个种子，LogMel 暂时更好；
- 视频：冻结 ResNet18 特征加轻量分类头，完成 pad/crop 对照；
- 离线：LogMel42 对 24 条真实语音完成断网推理、重复运行和中断恢复。

这些实验只验证了研究流水线。主要缺口是训练规模小、通用音频尚未训练、视频存在明显
尺寸/来源捷径、视觉主干和时序模型尚未验证、视频及大批量离线验收尚未完成。

## 3. 工作原则

1. **算法主线优先。** 时间优先投入数据覆盖、训练、EER 和跨域验证；工程只解决当前实验
   或交付的实际问题。
2. **一次校验、直接传递。** 配置和外部输入在入口校验，内部不重复解析同一事实；不为
   历史环境、无关文件或假想异常增加层层守卫。
3. **一次实验、一份结果。** 每轮保存配置、必要资产标识、逐样本分数、简洁摘要和必要日志；
   不复制整套脚本或为同一事实建立多份证明。
4. **探索与结论分开。** 小样本实验用于确定下一步，可以在明确局限下继续；严格统计只用于
   候选冻结和最终报告，不设机械的 bootstrap 组数作为训练前置门。
5. **最小可比改动。** 一轮实验只改变一个主要因素。比较时保持数据、划分、种子和评测协议一致。
6. **必要边界保留。** 数据许可、组级泄漏、留出集隔离、连续分数、非有限值和失败记账会直接
   影响结果，必须保留。

## 4. 数据与评测协议

### 4.1 数据登记和划分

样本清单记录 ID、相对路径、标签、模态、来源、原媒体/派生关系及已知人物或说话人、
生成器和内容类型。未知字段保留 `unknown`，不从文件名猜成事实。

同一原媒体的帧、切片、转码、增强副本，以及已确认的相同人物/说话人或近重复媒体，
必须放在同一划分。流程为：

1. 登记来源和许可，建立可解码的媒体清单；
2. 连接已知原媒体、派生和身份关系；
3. 按连通组生成 train/dev/holdout；
4. 使用 dev 做早停、模型选择、融合和阈值选择；
5. 候选冻结后只在 holdout 做最终验收。

近重复工具只产生候选关系；人工或可靠元数据确认后再写入分组。无法取得完整分组信息时，
报告局限并继续探索，不声称已证明未知生成器泛化。

### 4.2 EER

评测使用逐样本连续分数。项目实现处理并列分数、阈值插值、缺类与非有限值；所有正式实验
使用同一实现。失败样本计入覆盖率和失败率，不能只删掉后报告更好的 EER。官方评测程序
若后续提供，再用固定分数文件核对差异。

除总体 EER 外，候选冻结前至少查看：

- 来源与生成器分组；
- 音频的语音、音乐、环境声、音效等内容；
- 视频的内容类型、分辨率、编码、帧率和时长；
- 常见压缩、重采样或转码条件。

分组样本很少时只报告原始数量和描述性结果，不制造稳定性结论。

## 5. 音频路线

音频不能只覆盖语音。实施顺序如下：

1. **扩大 LogMel 基线。** 使用更多 ASVspoof 2019 LA 数据，确定 8GB 显存下的 batch、AMP、
   吞吐和稳定性，建立可复现的强基线。
2. **冻结 SSL 表征。** 使用已准备的本地 HuBERT 资源训练轻量媒体级头，与 LogMel 在相同
   split 上比较。只有明确收益后才考虑局部解冻。
3. **通用音频覆盖。** 对许可清楚的环境声、音乐和音效数据建立独立实验；EnvSDD 可在其许可
   范围内研究，归属工作不阻塞其他音频或视频实验。
4. **泛化实验。** 做来源留出、生成器留出以及重采样、编码和噪声扰动。优先选择平均 EER
   更低且退化更稳定的方法。
5. **融合。** 只有互补模型在独立 dev 分组上稳定获益时，才融合 LogMel、SSL 或 AASIST 分数。

AASIST-L 保留为对照。本轮小样本未优于 LogMel，且显存余量较小，不优先扩大。

## 6. 视频路线

当前冻结帧特征容易利用宽度和来源差异。实施顺序如下：

1. **消除捷径。** 平衡或分组控制来源、尺寸、编码和时长；加入宽度等元数据基线，确认视觉
   模型在控制后仍有增益。
2. **改进空间模型。** 在统一预处理下比较冻结主干与部分微调，优先使用 8GB 可承受的轻量
   backbone。先验证全帧，局部/人脸分支只有在数据表明有收益时加入。
3. **加入轻量时间信息。** 从帧差、相邻特征变化或轻量时序头开始；收益稳定后再评估更重的
   3D 或视频 Transformer 方法。
4. **跨域验证。** 按生成器、来源、内容、压缩和分辨率留出，确认模型没有重新依赖元数据捷径。
5. **媒体级聚合。** 比较平均、稳健平均或简单可学习聚合；选择必须基于 dev，不在 holdout 调参。

## 7. GPU 与实验执行

本地 RTX 4060 Laptop 8GB 默认用于训练、特征提取和推理。每种新模型先做一次小规模 profile，
确定 batch、精度、帧/切片数量、workers 和累积步数，然后直接进入计划实验。优先使用 AMP、
梯度累积和特征缓存；OOM 时先减 batch 或输入规模。

每轮最少记录：配置、数据 split 标识、种子、最佳 dev EER、训练耗时、峰值显存、失败数和
checkpoint。训练当前不支持 optimizer/RNG 恢复；中断后保留原目录，在新目录重新训练，不能
把推理的 `--resume` 当作训练续跑。

云算力只有在本地已确认方法有效、且预算获得明确授权后使用。

## 8. 离线交付

离线工作在候选有价值后推进，不为每次探索实验制作完整交付包。当前 CPU 音频小样本演练已
完成，后续需要：

1. 为冻结的音频、视频候选准备本地权重和依赖；
2. 在新环境断网安装并运行代表性批量输入；
3. 验证每个样本恰好一个结果，统计错误、吞吐、耗时和资源；
4. 验证中断后的推理恢复和最终输出格式；
5. 平台样例出现后更新 adapter，并重新执行一次完整验收。

离线包不包含训练数据、缓存、历史归档或研究日志。历史演练脚本只作证据，不作为当前通用入口。

## 9. 执行阶段与停止条件

| 阶段 | 当前任务 | 完成标志 |
| --- | --- | --- |
| A 工程收敛 | 合并重复入口和校验，保持数据/EER/评分行为 | 主线命令清楚，针对性测试通过 |
| B 音频基线 | 扩大 LogMel，训练冻结 SSL，补通用音频 | 至少一个覆盖更广的音频候选及分组结果 |
| C 视频基线 | 控制尺寸/来源捷径，微调空间模型，试轻量时序 | 模型在受控 dev 上优于元数据基线 |
| D 泛化选择 | 来源/生成器/处理条件留出，必要时融合 | 候选与配置在 dev 上冻结 |
| E 最终验收 | holdout 一次评测，双分支断网批量运行 | 结果、包、资源和已知限制齐全 |

停止或降级某个方向的条件：连续可比实验没有收益、收益来自元数据捷径、资源代价超过本地交付
能力、数据/权重许可不适用，或实现复杂度明显高于可验证收益。失败实验保留简洁结论即可，
不继续扩建证明体系。

## 10. 下一步

2. 扩大 ASV LogMel 训练，并运行已准备的 HuBERT 冻结头；

4. 在受控视频数据上比较主干微调和轻量时序；

6. 冻结候选后再完成双分支离线验收。
