## 本轮范围与顺序

本轮收敛当前代码和文档入口，减少重复校验、重复计算、历史绑定和脚本副本，把工作重心
移回训练与泛化验证。按以下顺序执行：

1. 统一 README、状态、实施方案、开发指南和配置说明；历史记录不再充当当前入口。
2. 在 `experiments.py` 复用统一 JSON 解析和来源记录；复用分组审计结果，删除调用方额外计算后
   丢弃的结果；训练配置解析后直接传递，不在内部层重复解析。
3. 将特征缓存身份收窄到媒体内容、预处理、编码器和 `media`/`features`/`encoders` 的实际
   特征提取实现；CLI、评测或文档等无关代码变化不再导致缓存失效。旧缓存按新键重新生成
   一次，不删除历史；实验报告仍保留完整源码身份。移除固定20GiB和32workers的配置天花板，
   保留用户设置的实际缓存预算与合法数值检查。
4. 在已有测试覆盖不足时先补最小行为回归，再删除重复实现；完成后运行针对性测试和标准检查。
5. 由独立评审核对行为与文档一致性，按 LoRA 原则拆分本地提交。
6. 本地、CI和文档共享 `tools/check_project.sh`，只维护一份标准检查范围。

本轮保留源与划分审计、缓存损坏检查、逐样本失败记账、连续分数、EER、权重加载和推理恢复。
配置只在外部边界校验，内部使用已解析对象。不新增通用离线框架，也不在本轮实现训练恢复；
训练恢复列为后续算法效率改进。
