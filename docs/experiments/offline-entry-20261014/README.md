接入统一媒体入口。CPU/GPU 演示、小批实际文件与故障恢复均完成，

## 包与执行条件

固定源码 `3783dc02feb7f1f4e5491d022402684a08cf6243`，包含 #58/#61/#62 的已审实现，
构建时工作区干净。包保持原权重、一个4秒音频窗口、四帧视频及既定空间预处理，
不晋级 CLIP 或三域音频研究候选，不新增依赖。

实际路径：
`/var/tmp/deepfake-offline54-20261014/relocated/deepfake-v0.1.2-rc1/`。
包内 CPython、Torch、NumPy 和项目源码已从搬移后的路径加载；
清除原虚拟环境、PYTHONPATH 和外部模型包变量，HF/Torch/XDG 模型缓存为空。

容器不允许新建 network namespace。本轮以临时
[Linux seccomp filter](https://www.kernel.org/doc/html/latest/userspace-api/seccomp_filter.html)
禁止目标进程及其子进程新建 IPv4/IPv6 socket，启动时同一 filter 内确认 TCP/UDP
的 socket/socketpair 均返回 EPERM，再执行真实包。普通文件和 UNIX socket 保留，
未向子进程继承网络 FD。这是可信程序的受限网络运行条件，不是恶意程序安全沙箱；
仍依赖主机 FFmpeg/ffprobe、系统共享库，以及 GPU 模式的 NVIDIA 驱动。

## 搬移与真实文件 profile

包内4条无标签解码演示，CPU/GPU 均4/4成功，失败0；包含44.1kHz双声道 WAV、
16kHz FLAC 和两条无音轨 MP4。CPU/GPU 端到端分别34.743/20.349秒，
包含包内 Python 路径与网络探针；最大分差 `5.2452e-6`。
这些人工信号不计算真假精度。

实际文件 profile 以两个 CUDA 进程并行执行，使用原媒体的本地独立副本。
来源、选择规则和完整清单保存在任务目录 `profile-selection.json`，其哈希见摘要。

端到端时间包含 Python 进程启动、发现、加载、逐文件评分和写出，父进程观测粒度约1秒；
进程启动时不加载模型缓存，但未清空主机文件页缓存，不能称为新机器冷启动。
单条时延来自子评分器记录，排除发现和模型加载，不能替代端到端时间。
RSS 来自 `wait4`，不是 GPU 显存。NVML 返回宿主 PID，无法可靠对应当前命名空间，
故每任务 GPU 峰值记为缺证，不将其他任务显存归入本次。

音频含语音、环境音、音乐各80条，分别取40 real/40 fake；按 ID 排序选取，
环境音与音乐的 fake 按生成器轮流取样。素材来自已见 In-the-Wild、Urban dev 和 AIME dev，
均为16kHz单声道，时长0.801–17.265秒。它们不覆盖全部格式或内容情形；
环境音默认权重能运行语音/音乐，不代表能正确鉴别。

视频为146条旧原始 dev 加其余六个生成器各9条 dev。
前者456×256、时长约3.04–3.79秒，后54条为448×256、2秒规范化版本。
这不是长视频、竖屏或完整编码覆盖。两批均未读取保留集，发现、选样和结果 ID 闭合，
无静默丢样本，空模型缓存仍为空；完整分布见 [summary.json](summary.json)。

## 万条真实语音容量

同一搬移包、原研究权重与预处理，在同一受限网络、空模型缓存条件下完成
10,000条真实语音文件：退出0，10,000/10,000成功，失败和未执行均为0。
端到端 **1,800.671秒（30分钟）**，包含进程启动、发现、输入身份、加载、评分与写出，
实际吞吐5.553条/秒；单条p50/p95/p99为0.1390/0.1483/0.1610秒，排除发现与模型加载。
`wait4`峰值RSS为1,719,484KiB；每任务GPU峰值仍缺可靠PID归属，不作显存结论。

来源为已用于#39/#41诊断的In-the-Wild注册test清单：每类按sample_id排序，
全局登记SHA去重后取5,000 real + 5,000 fake。入口实际SHA唯一数为10,000且逐项匹配登记值，
选择路径、发现、结果和分数ID全部闭合。原媒体2,863,551,136字节，全部hardlink，
未改媒体字节或inode权限，未读取保留holdout，也未计算EER或选模。

均为16kHz单声道，时长0.506–24.971秒，p50/p95/p99为3.390/11.370/18.941秒。
运行于队友任务并行的共享RTX4090，不是独占时限验收；仅证明此语音分布的运行容量，
不代表多域效果、完整格式覆盖或视频容量。首次发现期间约7分钟无分数写出，
最终端到端完整计入；probe、哈希、文件系统及模型加载未分别计时，不将这段全部归因probe。

产物在任务目录`audio-capacity/`；核心摘要见同目录[summary.json](summary.json)的
`audio_capacity`，完整选择与测量摘要哈希同时登记，不采用省略启动的万级投影时间。

## 故障与恢复

- 四条有效媒体加一个损坏 MP4、一个缺失 WAV：发现6项，4媒体成功、2发现错误，
  退出码2；仅产生4条模型分数，不编造失败分数。恢复后仍退出2，既有音视频分数字节不变。
  已登记媒体覆盖率为100%，全部显式输入成功率为4/6，二者不能混用。
- 20条实际音频持久写入3行后，对核验过的本次进程组发送 SIGINT，退出 `-2`；
  输入身份与3行分数保留。同输入、同输出恢复后退出0、完成20/20，原3行逐字节保留。
  未修改恢复身份，也未影响其他任务进程。

故障首跑/恢复耗时15.540/16.337秒；中断/完成恢复耗时15.690/18.651秒。
复用 #57 已有输入行为回归，本轮没有再建发现或评分引擎。
