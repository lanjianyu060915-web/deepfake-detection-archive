## 环境音预处理与音频范围

新版 checkpoint 显式采用 `center_pad_64000_peak095_v1`：解码至16kHz单声道，
居中裁剪/两侧补零至64,000点，非静音峰值0.95。训练缓存与推理共用该函数。
所有模型 tensor 与 v0.1.0 相等，仅迁移配置；旧 checkpoint 缺少字段时保持 legacy。
这不等于不同解码器/重采样器或 PCM16 量化逐位一致。

音乐和语音使用既有离线研究包的固定 dev 子集，未按新分数重新筛选。
Urban 已训练桶与旧推理2885条ID一致，EER保持1.3865%；分数最大差0.00030220、
平均差0.00000767。该桶输入已预先裁剪/补齐/归一化，因此不能用小差异否认原始任意媒体
上旧训练/推理不对称的问题。

结论：修正波形策略没有让环境音模型获得通用音频能力。音乐22.50%、语音44.00%
直接阻止把它作为通用音频最终候选；三域联合训练继续由 #41 推进。
新版配置名为 `audio-environment.json`，发布元数据明确 `general_audio_ready=false`。
AST 上游默认 NumPy 前端的空 mel 列告警保留，未通过改 FFT 或抑制 warning 改变输入。

## 视频尺寸、帧率与时长控制

先核对既有原始分数：v0.1.0 发布视频权重 `16abc4e…` 已有全量1949条、19生成器评分，
104 real / 1845 fake，EER31.3279%、覆盖率1.0、0失败；不是只评测过310条。
此处从原逐样本分数复算，未重复跑原始媒体。冻结头原记录为33.2791%。

原始宽度 oracle30.42%，原310条尺寸控制子集的时长 oracle21.24%，都说明当前数据存在
捷径。新增条件 `video_h264_crf23_448x256_16fps_3p5s` 通过现有
`tools/prepare_robustness.py` 将真假都转为448×256、SAR1、16fps、56帧/3.5秒、
H.264 CRF23/yuv420p、去音轨。3.5秒在查看新模型分数前按全1949条最短3.8125秒确定，
不按标签或效果删样本、不对短视频循环补齐。生成后逐条确认时长和帧数。

## 离线运行与许可边界

裁剪后的运行包在仓库/共享虚拟环境之外、禁用 Hugging Face 联网的环境启动：
CPU/GPU各完成两条音频和两条视频演示；GPU完成18音频+12视频真实dev，均零失败。
混合输入一个损坏WAV与一个正常FLAC时，退出码2，CSV只导出正常样本，
sidecar记录2条输入、1条失败、覆盖率0.5；恢复后保持同一结果。
这些是可执行性结果，小样例EER不作为泛化结论。

运行依赖按 wheel 元数据闭包复制，保留 Triton/CUDA；不随包分发系统 FFmpeg。
本次工程修复不能确认 UrbanSound8K/Panda/HD-VILA 的参赛许可，
`competition_use=unconfirmed` 保持不变，详见[发布资产条款](../../release-licenses.md)。
