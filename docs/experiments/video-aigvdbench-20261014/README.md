# AIGVDBench 新来源视频开发集

冻结CLIP头43在统一处理的1880条新来源dev上EER **31.33%**，
优于七生成器ResNet的39.00%，改善7.67个百分点。收益仍不均匀，
Luma与SEINE各42.50%；保留CLIP为后续视频研究主候选，尚不替换发布权重。
自然与受控两组均已完整完成；自然组CLIP21.33%，但处理条件差异明显，
以两组同时判断候选，不把自然成绩当作盲测或比赛结果。

## 数据与协议

复用 #51 的 AIGVDBench，revision `bf48acaa4920990af3dd2a511ea88e63354df305`。
仅使用dev：600真实、600配对Open-Sora及另17个生成器各40条，共1880条。
真实来自官方val，已登记的同YouTube母视频与对应Open-Sora同组；
未读取或用保留部分选模。Open-Sora与单独的Opensora是两个登记名称，不合并。

受控媒体两类一致处理为448×256、16fps、1.25秒、H.264 CRF23、无音轨，
原始字节保留。真实原片均1080p且较长、假视频通常更小更短；因此先以受控组
比较，再以自然组观察处理条件变化，不能只靠原始组判定泛化。

CLIP使用已冻结的seed43/epoch16头与同一UFD ViT-L/14骨干，FP32、四帧、
视频级帧logit均值，直接输出连续logit。没有新训练、翻转方向或按本集重选seed。
四候选保持同一四个采样时间点；CLIP使用必要的native center crop，
ResNet使用center crop；batch分别4与8。它们是完整候选对照，不能仅归因骨干。

## 完整自然媒体结果

复用同一批dev的原始媒体，四候选均1880/1880、零失败，保持各自原协议。
不重跑队友对照；[自然组配置](infer-natural.json)与逐生成器数值见核心摘要。

| 候选 | pooled EER | 去Open-Sora | 配对Open-Sora/real |
| --- | ---: | ---: | ---: |
| v0.1.1视频 | 55.00% | 44.12% | 66.83% |
| 七生成器ResNet43 | 43.36% | 36.76% | 49.83% |
| 时序头43 | 52.73% | 42.94% | 63.17% |
| 冻结CLIP头43 | **21.33%** | **20.83%** | **21.83%** |

CLIP自然组比受控组低10.01个百分点，但处理同时改变尺寸、裁剪覆盖、时长、
帧率与重编码；不能把差值仅归因于格式捷径或生成痕迹。绝对效果仍依赖输入条件，
不据自然组更低的EER推翻预先以受控组为主的比较，也不将已见dev当最终盲测。

自然组曾分段恢复，原274行及第二次恢复前1414行均逐字节保留；最终exit0。
只有最后466条续跑有完整wall记录1,945.69秒，此前一次进程停止未保存完整计时，
故不拼造总端到端耗时。1880条逐样本计时合计3,858.93秒，不包含全部启动/索引开销。

## 4/8帧有界对照

只改变均匀采样帧数，头/骨干、媒体、FP32、batch4、裁剪和mean logit聚合相同，
8帧改变中间时间点，不是原4帧的严格超集。两组各1880条、全覆盖、零失败。

| 条件 | 4帧 | 8帧 |
| --- | ---: | ---: |
| pooled EER | **31.33%** | 31.80% |
| 去Open-Sora EER | **29.85%** | 30.83% |
| Open-Sora/real配对 EER | 32.67% | 32.50% |
| 实际端到端秒数 | 726.69 | 797.39 |

8帧pooled退化0.46个百分点、去Open-Sora退化0.98个百分点；
Luma42.50%→41.67%，SEINE仍42.50%。资源与逐生成器结果见核心摘要的
`frame_count_trial`，[8帧配置](infer-controlled-8frames.json)保存实际参数。
两次共享负载不同，耗时+9.73%只描述本次运行。**保留4帧，停止堆帧**，不继续试16帧。

## 资源与复现

实际CLIP评分源码 `32f027e`，GPU为共享RTX4090，固定FP32、batch4。
完整受控组726.69秒；allocated峰值1.337GB、reserved1.380GB。
解码/预处理474.50秒、特征/模型209.77秒；这些是该次共享负载结果，不能外推其他GPU吞吐。

固定[推理配置](infer-controlled.json)保存当时实际路径。完整分数、metadata与必要日志位于
`/var/tmp/deepfake-video-independent-20261014/`；队友对照位于
`/var/tmp/lanjianyu-issue51-20261014/aigvdbench/scores/`。
头与骨干已存C6持久归档，模型SHA与本次分数SHA见核心摘要，不重复复制模型或原媒体。

```bash
scripts/devctl run python -m deepfake_detection_archive infer \
  --config docs/experiments/video-aigvdbench-20261014/infer-controlled.json
```

重跑需更换输出目录；已有分数通过标准`--resume`续跑。配置内路径是实验事实，
迁移时按[数据资产](../../data.md)映射到本地副本，不默认重新下载。

## 局限与下一步

新数据来源不等于已证实母媒体独立。旧Panda训练/选择清单没有可确认的YouTube原始URL映射，

新数据内部登记隔离不能补足这项证据，未据此构造“已清洁”子集。

数据卡标CC-BY-4.0，底层YouTube权利仍未核实，仅作研究/评估。
绝对EER仍高，未知来源和全部视频任务能力尚未解决，不能当比赛成绩。

双条件与帧数对照已完成，停止堆帧；下一实验复用已有4帧CLIP缓存，
接入项目现有轻量Conv1d时序头，在原train/dev上有界训练，按原dev选择后再比较本dev，
区分“增加观测数”与“学习帧间关系”。不重提冻结主干、不另建训练框架，保留部分继续封存。
