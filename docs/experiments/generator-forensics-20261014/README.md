# 生成机制鉴伪：WaveRep 对照、VAE 重建受控实验与机制辅助训练

把生成器的输出解码器（VAE）当作可测机制，做了四件事：一个公开机制检测器（WaveRep G1）的作者对齐与同协议评分、
一个图像 AE 重建受控实验（AEROBLADE 思路，SD1 VAE）、一个匹配视频 3D VAE 的连续片段实验（Wan2.1 VAE），
以及一次单因素机制辅助训练（T1：VAE 重建配对代理样本）。**全部 0 失败、覆盖率 1.0。**

## 结论

- **WaveRep G1 与冻结 CLIP 头互补，固定融合在新来源dev上降低4.85个百分点，保留为研究融合候选。**
  G1检测训练只用Pyramid Flow及其VAE重建样本；本项目新dev含Pyramid-Flow40条，并非全部未训练生成器。
  G1真实检测训练素材来自Panda70M，与旧ViF/Panda属于同一来源族；母媒体交集尚未确认。
  这些说明仅覆盖检测器训练，不覆盖主干/VAE的预训练接触。单模型在AIGVDBench新来源dev（1,880条）
  31.41%，与 CLIP43 的 31.33% 持平；去掉 600 对内容配对的 Open-Sora 后 20.67%（CLIP 29.85%）。
  只在原选择dev844（资产中名为new-dev）拟合的CLIP43+WaveRep，在AIGVDBench dev1880上 **26.48%**，在 1949 历史诊断 24.04%（CLIP 26.56%）、
  crf35 23.98%（25.84%），6 个 VAE 家族全部改善；拟合集 new-dev 上 25.36% 对 24.64% 略差，这是 CLIP 的训练分布。
  作者公开真实视频列表共2000个YouTube ID；与本项目提取出的文件名候选未发现匹配。
  旧Panda缺原始URL映射，不能由候选交集0证明与本项目全部真实母媒体独立。
  代码与权重为非营利许可，**正式赛用须负责人先确认**；不替换发布默认。
- **相对 #48 ResNet（本单预先声明的主对照 B）**：WaveRep 在 1949 上 27.88% 对 31.73%、未训练标签 28.40% 对 33.14%；
  但在 B 的训练分布 new-dev 上 31.75% 对 30.09%，对再编码、CRF35、缩放的退化也更大（频域线索对压缩敏感）。
- **H2（AE重建误差）在本轮数据和配方下未获支持。** SD1 VAE 只在“重建它自己的输出”时有效（正对照 19.43%），
  对真实生成视频 43–47%，像素 L1 甚至反向；匹配 Wan2.1 VAE 的片段重建在 Wan2.1-VAE 家族上也无优势（45.1%），
  连检测它自己的重建样本也只有 41.71%：本次3D因果VAE重建方案没有形成可采用收益。
- **H3（3D VAE时间结构）在本轮实验中未获支持。** 片段内按 4 帧相位的重建误差模式在真实视频与所有生成家族中相同，是编解码结构而非生成痕迹。
- **H4（VAE 配对代理训练）在现有 ResNet18 管线上为负结果。** T1 在 dev 33.41%、诊断 34.62%、未训练标签 35.58%，
  全面差于 T0；T1 对未见过的同类代理样本仍为 49.05%，未表现出对该代理痕迹的有效区分。
- **本轮结果与重采样削弱解码器线索的解释一致。** 同一批 150 条真实视频，Wan2.1 VAE 在 448×256 上直接重建时
  WaveRep 可分 36.00%；改为在生成器原生 832×480 解码、再按 canonical 规则 bicubic 缩回后升至 44.67%。
  该对照同时改变VAE工作分辨率和下采样，未单独隔离每一步。
  224缩放可能削弱线索，尚不能确认是T1失败的唯一原因；WaveRep原分辨率裁剪是需保留的输入条件。
- **决定**：CLIP43+WaveRep 固定融合保留为**研究候选**；采用前完成标准入口的完整评分、冻结保留验收与赛用许可确认；
  本单提供可注册的 `waverep_video_v1` 适配器与权重准备工具，融合接口交 #57 协调。AE 重建、3D VAE 片段、
  T1 训练增强停止；DIRE/FakeInversion本轮不展开；停止当前重建方案，不由此否定所有重建检测方法。不修改发布默认，不新增依赖。
  若继续机制路线，可检验原生裁剪上的配对训练；它属于后续有界实验，不是本轮已经证实的有效方案。

## 方法与协议

认领与全部预先固定项在 [#59 评论](https://github.com/lanjianyu060915-web/deepfake-detection-archive/issues/59#issuecomment-6164847345)
登记于评分之前，执行中未修改：主对照、选择用 dev、分数方向、聚合、WaveRep 只用 G1、首轮只用 SD1 VAE、融合规则与停止规则。
登记时写明“#51 独立来源数据交付后只用其开发部分”。本单收尾时#51已交付AIGVDBench dev，冻结CLIP头#61已通过#64进入main，新来源实验卡由#68交付，
因此追加了一次比较：规则（单模型、只在 new-dev 拟合的融合、去 Pyramid-Flow）在给 WaveRep 评分之前写定，
但这批 dev 不是认领时声明的选择集，采用决定据此属于**事后补充的新来源开发证据**，正式采用前应在新的保留集上再验一次。

- **WaveRep**：作者仓库 `0fd6010`；timm `vit_base_patch14_reg4_dinov2.lvd142m`，`img_size=504`，原分辨率
  `CenterCrop(504)`（不足处补零）、ImageNet 归一化、FP32，视频分数为逐帧 logit 均值。权重为裸 state_dict，
  `strict=True` 加载 0 缺失/多余键。比赛管线用项目 `decode_video` 的 4 帧索引规则在原分辨率解码；另评作者demo的顺序全帧方式（本项目短片段≤56帧）；论文使用前64帧，四帧是本地变体，不能称完整复现论文采样协议。
- **作者对齐**（预先固定样本：new-dev 按 ID 排序的前 4 真 4 假；容差 1e-3）：同一张量预处理差 0，cv2 与 FFmpeg 解码像素逐位相同，
  逐帧 logit 最大差 3.93e-5，视频分数最大差 2.4e-6。唯一改动是 `pretrained=False` 以禁止隐式下载，权重随后被严格加载完全覆盖。
- **SD1 VAE 重建**：`CompVis/stable-diffusion-v1-1` 的 `vae`（`574555a`，FP32），原生 448×256 不缩放；
  后验 mode（作者为采样；100 条上两者分数相关 1.00000、平均相对差 1e-4），重建按作者 PNG 保存方式截断到 8 位；
  距离复刻作者 `_PatchedLPIPS` 第 2 层（VGG 第二阶段、lin 层、不上采样的空间均值）。
- **Wan2.1 VAE 片段**：`Wan-AI/Wan2.1-T2V-1.3B-Diffusers` 的 `vae`（`0fad780`，Apache-2.0），每个视频取第 8–24 帧共 17 帧
  （1+4×4，跳过首个关键帧），后验 mode，逐位置记录 LPIPS 与 L1，文件分数为 17 个位置的均值。
- **派生集**：全部由解码 RGB 经同一 x264 设置（preset medium、yuv420p、16fps、SAR1）生成；A(R) 的 Wan 重建对不满 1+4k 的帧数
  复制末帧补齐、解码后丢弃。派生集只用于诊断，未进入任何训练或选择。
- **T0/T1**：配方与 #48 自然配对 seed43 完全相同（3,614 条训练、BF16、batch64、最多 25 轮、patience 6、按 new-dev 选轮）。
  T0 在当前 commit 复跑得到与冻结权重**逐字节相同**的 `1d7cb9f5…`。T1 唯一改动：真实父样本 ID 的 SHA-256 为偶数的 931 对中，
  生成假样本换成该真实视频的 Wan2.1 VAE 重建（训练集 1,807 条真实视频全部重建，0 失败），样本数、类别平衡、更新次数不变。
  混杂：等量替换同时使真实生成样本减少 51.5%，因此 T1 的退化不能只归因于代理样本本身；但 T1 对代理样本也无区分力，
  且在其覆盖的 Wan2.1-VAE 家族同样退化，本轮管线未学出可采用的代理区分。首轮负结果，未做第二种子。

## 离线适配与交接

新增 `waverep_video_v1`（`src/deepfake_detection_archive/models/waverep.py`）：timm 以 `pretrained=False` 构建同一网络，
全部参数来自本地 checkpoint，不联网；`video_frames` 路径要求 PR #58 的 `native_center_crop` 且尺寸为 504，
否则拒绝加载。`tools/prepare_waverep.py` 先校验作者权重 SHA-256（`1c7566b2…`），再按作者
`create_model` 的键规则严格加载、转存为自包含 checkpoint（`35659dbd…`，旁附 `.resources.json` 记录许可与预处理）。

标准 CLI（4 帧、504 native crop、FP32、batch8）在 new-dev 844 条上 0 失败，EER 31.75%，与研究路径完全相同；
逐文件 logit 平均差 0.0064、最大 0.154，来自解码滤镜链差异（标准入口在 FFmpeg 内完成 RGB 转换与补零裁剪），
该844条的EER相同，不保证逐样本排序或新来源融合分数完全相同。耗时353秒（含解码，共享 GPU）。

26.48%是研究路径融合结果，尚非公共入口端到端实测；标准入口需要沿冻结系数重新形成完整分数，不能直接沿用该指标。

本轮收尾时融合尚未进入公共入口：需要 #57 支持“两个视频模型各自评分后按固定仿射+逻辑回归合成一个分数”。
最小接口差异是在预测配置中登记两个 checkpoint、各自的视频配置与本卡 `summary.json` 的
`clip43_waverep_fusion` 参数（均值、标准差、系数、截距），先后各解码一次；由 #57 负责人决定实现方式。
发布默认、现有模型数值行为与依赖均未改变（timm 已在项目依赖中）。

后续 #72/#76 已完成固定融合接入，并经 #78 合入 main：标准入口1880/1880、零失败，
EER26.40625%，没有重新拟合或读取holdout；见[标准融合实验](../video-fusion-20261016/README.md)。
上述26.48%仍保留为原研究路径阶段结果，不能与后续标准分数混用。
