## 算法取舍

- 语音已比较 LogMel 与冻结 HuBERT 头，本轮 LogMel 两种子均更优；AASIST-L 为历史对照。
  主干微调、增强或融合由可比结果决定，避免同时改模型、数据和采样。
- 非语音AST部分主干微调优于同集HuBERT，双种子本地dev EER2.86%/5.71%。
  原单生成器研究候选holdout为11.43%，直接迁移新Urban dev EER33.62%。
  扩展数据后12层微调达到同一新dev1.39%、未见生成器dev5.03%；补seed43为1.65%/3.73%。
  音乐单独训练损失环境音能力，已完成两种混合采样对照；未训练音乐仍是下一数据投入重点。
  语音 SSL 的效果不能代替通用音频验证，FakeSound 的 fake-only 不能代替配对评测。
- 视频已跑出受控空间结果；当前逐帧特征均值不具备时序建模能力。
  新生成器诊断与同划分部分微调独立并行，取得结果后再决定轻量时序；不一开始建设大型视频 Transformer 工程。
- 泛化优先未知攻击、未知来源和压缩退化。小桶用于寻找下一实验，不强求统计显著性；
  需要正式结论时才扩大样本并冻结测试协议。
- 单因素连续没有收益、明显依赖元数据捷径、资源代价超过交付能力的方向停止扩展。
  失败实验保留数量、结果和结论，不复制证明树。

## 系统完成条件

当前训练、评分、指标和打包代码已经存在。系统完成需要把这些入口接上**有效候选**：

1. 音频与视频均有本地可加载的已选择模型及明确适用范围。
2. 输入清单经确定的采样/解码进入模型，每样本产生一个分数或失败记录。
3. 在冻结后的 holdout 和代表性离线批量上报告 EER、覆盖率、时间和资源。
4. 离线包包含所需权重、运行依赖、配置和许可；官方 I/O 到来后完成适配。

训练 optimizer/RNG 恢复尚未实现。短基线不为它延期；长任务确有中断成本时再补。
仅有测试通过、合成前向或打包工具，不能视为上述交付完成。

## 维护规则

项目文档只有使用指南、当前状态、路线图、数据/许可及简洁实验结论。
Issue 是任务状态来源，PR 是代码交付；不维护个人交接 Prompt、会话流水和重复任务正文。
代码或输入在边界校验一次，内部传递已解析对象；训练缓存准备时核对，epoch 内直接读取。
代码变更先运行相关行为测试，提交前一轮标准检查，不把检查报告当作算法里程碑。

每个实验在 `outputs/<任务>/<run>/` 保存配置、必要数据/模型标识、训练日志、最佳权重、
逐样本分数和摘要。Git 只提交可复现配置和[实验卡](experiments/README.md)中的结论。
整理前的过程文件可在 Git 提交 `4bbd292` 查阅，后续不继续生成同类文件。

文档组织借鉴 [AASIST](https://github.com/clovaai/aasist#readme) 的数据/训练/评测顺序、
[DeepfakeBench](https://github.com/SCLBD/DeepfakeBench#-quick-start) 的配置和结果入口，
以及 [ASVspoof](https://github.com/asvspoof-challenge/2021/tree/main/eval-package) 的评分与指标分离。
仅借鉴项目组织，不引入其框架或旧依赖。
