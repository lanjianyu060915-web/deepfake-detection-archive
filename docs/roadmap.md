# 比赛路线图

目标是音频、视频各有有效候选，能在离线环境批量输出连续分数，以EER评估。
已经完成的实验只在[实验索引](experiments/README.md)维护；当前选择见[项目状态](status.md)。

决策点：

- D1 选模：两档都满足各域上限，取平均EER低者；只有一档满足取该档；都不满足回#41调整采样。
- D2 第二轮：联合候选语音8kHz带限EER比带宽增强LogMel高3个百分点以上才做；否则GPU优先给#40。
- D3 音频冻结：各域在上限内、平均EER最低，且两种子相差不超过1个百分点；同分取结构简单、推理快者。
- D4 视频替换：固定跨生成器诊断比v0.1.1好2个百分点以上且无分组明显退化才换主候选，否则只作第2份结果。

每项目三份结果：

| --- | --- | --- |
| 1 稳妥 | 冻结的三域主候选 | v0.1.1部分微调 |

| 3 备选 | 双种子等权分数融合（离线推理支持双模型后） | 四帧时序头研究候选 |

每份对应一个配置，用一条`./run.sh predict`可复现。

调试期清单：

1. 读平台输入目录、样例与输出格式，更新比赛要求中“尚未公布”一表。
2. adapter转换标签与分数方向（内部`fake=1`、高分更伪造；FAR/FRR按官方定义），核对文件名与精度。
3. 用平台样例在安全屋各跑小批量，核对Python/CUDA、显存和FFmpeg（运行包不含FFmpeg）。
4. 平台GPU与4090不同时，用小样本确定batch，必要时`--device cpu`。
5. 冻结日前提交三份结果的配置，冻结后不改代码。

资源与风险：4090同一时间只跑一个训练加一个推理，开工和结束在对应Issue记录，两档同时训练会明显拖慢；
`/var/tmp`不是持久卷，冻结候选的权重、sidecar、逐样本分数和v0.2.0包须另存持久存储并核对sha256；
窗口提前时以v0.1.1先交；视频跨生成器最弱，GPU优先#40；单种子结论不稳由D3把关；许可未落实的资产不进正式结果。

## 当前算法取舍

- 语音保留带宽增强LogMel42研究候选，原基线作对照；带限已改善，跨来源仍未完成。
- 环境音保留冻结AST研究候选。音乐扩展与时频遮挡有取舍，等权融合仅是dev分数探索，
  尚未实现双模型离线推理；是否采用须结合泛化和实际成本。
- 对称音乐/语音混合改善合成条件，但真实广播混合仍50%、环境音退化，不替换主候选。
  下一投入是独立来源和真实混合数据，减少围绕同一合成dev的参数搜索。
- 视频部分微调改善同域dev；全1949条统一尺寸/帧率/3.5秒后EER33.12%，冻结头33.65%，跨生成器优势仍弱。
  H.264增强只保留同域压缩用途，不替换原微调主候选。
  四帧时序头已完成双种子训练，汇总跨来源略优但分组有退化；结合#40的新训练来源
  再比较结构收益，不围绕当前小dev反复调参。

## 系统完成条件

1. 音频与视频都有本地可加载的已选择模型和明确适用范围。
2. 每个输入产生一个连续分数或失败记录，解码和模型失败不静默丢弃。
3. 代表性离线批量有覆盖率、耗时和资源结果；冻结最终候选后做独立holdout验收。
4. 运行包包含本地资源、依赖、配置和许可；v0.1.1已按项目I/O交付，官方样例明确后适配平台格式。

工程只解决当前训练和交付问题。每轮保留配置、必要资产标识、分数、摘要及必要日志；
完整运行产物放Git外，历史通过Git追溯。相关回归先覆盖改动，提交前一轮统一检查，
没有新改动或失败就不重复测试；检查通过本身不计为算法成果。
