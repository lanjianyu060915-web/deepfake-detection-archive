# 比赛路线图

目标是音频、视频各有有效候选，能在离线环境批量输出连续分数，以EER评估。
已经完成的实验只在[实验索引](experiments/README.md)维护；当前选择见[项目状态](status.md)。

## 后续顺序

| 优先级 | 方向 | 下一步与完成条件 |
| --- | --- | --- |
| P0 | 语音泛化 #29 | 完成带宽增强，比较clean、8kHz带限和未知攻击；保留或停止以可比结果决定 |
| P0 | 视频泛化 #30 | 控制尺寸混杂后比较冻结/微调候选，完成压缩增强；再决定是否投入轻量时序 |
| P0 | 通用音频 #32 | 补独立音乐来源与真实混合内容；改善跨来源，同时控制纯音乐/环境音退化 |
| P0 | 离线系统 #31 | 接通AST与微调视频，完成代表性断网批量；记录覆盖率、时间、显存和失败 |
| P1 | 候选冻结 | 根据泛化与资源选定音频/视频方案；冻结代码、配置和权重后验收独立holdout |
| P1 | 比赛交付 | 打包本地依赖、权重和许可；官方样例到来后适配I/O，完成两批万级媒体容量演练 |

四条P0可独立推进，GPU按实际余量共享。未知平台细节集中在
[比赛要求](competition/requirements.md)，不阻塞现有公开数据研究。

## 当前算法取舍

- 语音保留LogMel42；当前最明确弱点是带宽变化，冻结HuBERT未改善同域结果。
- 环境音保留冻结AST研究候选。音乐扩展与时频遮挡有取舍，等权融合仅是dev分数探索，
  尚未实现双模型离线推理；是否采用须结合泛化和实际成本。
- 对称音乐/语音混合改善合成条件，但真实广播混合仍50%、环境音退化，不替换主候选。
  下一投入是独立来源和真实混合数据，减少围绕同一合成dev的参数搜索。
- 视频部分微调改善同域dev；跨生成器有尺寸捷径，先控制分布，再决定时序方法。

## 系统完成条件

1. 音频与视频都有本地可加载的已选择模型和明确适用范围。
2. 每个输入产生一个连续分数或失败记录，解码和模型失败不静默丢弃。
3. 冻结后的独立验收及代表性离线批量有EER、覆盖率、耗时和资源结果。
4. 运行包包含本地资源、依赖、配置和许可，按实际平台格式交付。

工程只解决当前训练和交付问题。每轮保留配置、必要资产标识、分数、摘要及必要日志；
完整运行产物放Git外，历史通过Git追溯。相关回归先覆盖改动，提交前一轮统一检查，
没有新改动或失败就不重复测试；检查通过本身不计为算法成果。
