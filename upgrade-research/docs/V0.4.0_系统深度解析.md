## 3. 任务生命周期与数据契约

### 3.1 任务目录

每次运行创建 `runtime/tasks/case_YYYYMMDD_HHMMSS_<4hex>/`（正式版在 `%LOCALAPPDATA%\FaceSourceTrace\tasks\`）：

```text
logs/progress_latest.json       最新事件原子快照
logs/progress.json              v0.2 兼容数组
logs/<module>_stdout.log / _stderr.log / _command.json
```

### 3.2 状态机

- 未选择模块 → `skipped`；任一模块失败不阻断其他模块。
- 任务总状态：3/3 成功 `success`；至少一个成功、至少一个失败 `partial_success`；全失败 `error`。
- 单模块结果由 orchestrator 统一校验：字段缺失或类型错误 → 视为模块失败并写入结构化错误。

### 3.3 进度事件

- 模块取值：`overall` / `deepfake` / `identity` / `source`；状态：`pending/running/success/warning/error/skipped`。
- 节流：约 0.5 秒或约 5% 变化；百分比只来自可度量阶段，不可度量时为 `null`（不伪造进度）。
- 写入：`progress_events.jsonl` 追加 + `progress_latest.json` 临时文件替换；跨进程文件锁。

### 3.4 结果 schema 3.0

三个模块结果共通字段：`method`、`metrics`、`explanation`、`warnings`、`limitations`、`runtime`、`provenance`。

- AIGC：`label`、`is_deepfake`、`score`、空间/频域分、融合权重、阈值、输入哈希、模型哈希、设备、有效帧/人脸计数；证据不足时 `score=null`。
- 身份：查询人脸数、选择框、检测分、512 维特征、库规模、有效 embedding 数、人员均值聚合、逐参考图相似度、最佳参考图、Top1−Top2。
- 底图：人脸屏蔽信息、图库解码/跳过数、粗排数、全局/局部/最终分、关键点数、Lowe 有效匹配、RANSAC 内点/内点率、局部分量、权重、Top1−Top2、匹配可视化。

### 3.5 报告

- 生成器 `deterministic_template_v3`：本地确定性模板，离线、不调用外部语言模型。
- 支持成功、部分成功、失败、跳过模块；缺失值不补造结论。
- 普通视图只显示文件名；完整路径保留在 JSON 与技术详情。

## 4. 模块一：AIGC 换脸/深伪风险甄别

### 4.1 模型与权重

| 组件 | 文件 | 大小 | SHA-256 |
|---|---|---:|---|
| 空间域模型 | `models\spatial_mobilenet_finetuned_gpu\spatial_mobilenet_finetuned_gpu.pt` | 6,202,455 B | `5bb4b33936eb3adc631828ea271a466d62070a2b8de1902e5d96122317534794` |
| 频域模型 | `models\frequency_stat_formal\frequency_stat_detector.joblib` | 4,129 B | `2ec6828eb2a3151784667eb0c105f07cdb41de6ec2df587d28b2766ceee063eb` |
| 融合配置 | `models\fusion_formal\fusion_config.json` | — | `8f76abeabb55da1119b28689e15ccd31eac7f1066e401e766987efbb4603e0b2` |
| 适配层 | `modules\deepfake_detection\run_deepfake_detection.py` | 29,158 B | `373ce764a5b05c03c56b204414218df6ef7d4d8173ecba696f4b189b587f0f3b` |

空间域：MobileNetV3-Small 二分类（REAL=0 / FAKE=1），完整 checkpoint（含 backbone 与分类头），推理不需要官方预训练权重（官方权重仅用于 `MobileNet_V3_Small_Weights.DEFAULT` 的标准化 transform）。训练细节（元数据）：145 张验证集、最佳 epoch 15/20、验证 AUC 0.7892、阈值 0.1951、仅 [10,11,12] 三个特征层解冻、训练设备 RTX 5060、随机种子 20260712、训练 297 秒。

频域：87 维 FFT/DCT/噪声/统计特征 + `StandardScaler + LogisticRegression`；训练 678 / 验证 145 / 测试 150 帧；阈值 0.3247。

### 4.2 融合与阈值

```text
fusion_score = 0.62 × spatial_score + 0.38 × frequency_score
帧阈值      = 0.36360106194654707
视频聚合    = median（本系统只接单图，视频路径未启用）
视频阈值    = 0.4583425493641632
```

权重与阈值来自 145 样本 / 30 视频的验证集选择（选择指标 ROC-AUC，差异 0.002 内再用 F1/准确率/简洁性），测试集未参与选择。

### 4.3 推理执行方式（关键机制）

1. 适配层要求 Python 3.12（`-E -S -B` 启动 portable Python，隔离 site/user/site-packages 与字节码写入）。
2. `pyinstaller_pyz_runtime.py` 直接解析已安装 `深度伪造识别系统.exe` 的 PyInstaller CArchive 与 PYZ，把归档内纯 Python 模块挂到 `sys.meta_path`；但对 `src.*` 优先使用磁盘上的受控源码覆盖层（`deepfake_runtime\src\`），即**推理源码是可读、可审计、可替换的**。
3. `TORCH_HOME`、matplotlib 缓存等重定向到任务可写目录；DLL 目录显式加载 `deepfake_runtime` 与 `torch\lib`。
4. 设备强制 CPU：`SpatialMobileNetDetector` 明确拒绝非 CPU 设备；CUDA 路径仅在错误分类中保留（失败则 CPU 重试）。
5. 预处理：OpenCV 解码 → Haar 主脸 → 扩边 25% → 224×224 → ImageNet transform。
6. 错误分类：`MODEL_RESOURCE_MISSING` / `MODEL_CHECKPOINT_INVALID` / `NO_VALID_FACE`（→`insufficient_evidence`）/ `INPUT_IMAGE_INVALID` / `CUDA_RUNTIME_FAILURE` / `AIGC_RUNTIME_FAILURE`。

### 4.4 证据输出

真实 Occlusion Sensitivity、FFT/径向频谱、87 维有符号贡献、动态阈值图；空间图是「模型敏感性」而非像素级伪造定位；无专用五点关键点模型，仅展示 OpenCV 实际检出的眼部候选。

### 4.5 性能

- 持久 worker 模型只加载一次：100 张批量（含证据图）86.1 秒，平均 0.86 秒/张。
- 加载 + 单图冷启动约十余秒量级（受磁盘影响）。

## 5. 模块二：人脸身份候选检索

### 5.1 模型与特征

- 模型包：InsightFace `buffalo_l`，随包 5 个已批准 ONNX（检测 det_10g、关键点 2d106、姿态 1k3d68、性别年龄 genderage、识别 w600k）。
- 推理：`insightface.app.FaceAnalysis`，`det_size = 1280×1280`，`ctx_id = -1`（CPUExecutionProvider），离线策略 `enforce_offline_import_policy()` 禁止运行时下载。
- 特征：512 维 float32，L2 归一化；相似度 = 两个 L2 归一化向量的点积（等价余弦）。

### 5.2 检索规则

1. 查询图必须**恰好一张人脸**；0 张或多张均返回结构化错误（含真实诊断：人脸数、各框、检测分）。
2. 同一人多名参考图：对全部有效参考图相似度取算术均值，按人员均值降序；人员 ID 作为稳定并列键。
3. 输出 Top-K（默认 5）：人员均值、逐参考图相似度、最佳参考图、Top1−Top2 间隔。
4. 无开放集拒识：正式配置 `open_set_rejection_enabled=false`；库外样本仍返回相对 Top-K。

### 5.3 缓存

- JSON + NPZ 双文件缓存，带图库文件清单 / 模型 / 预处理指纹；校验 schema、文件 SHA-256、顺序、shape、dtype、有限值。
- 缓存命中失效自动重建；缓存目录开发版 `runtime/cache/identity`，正式版 `%LOCALAPPDATA%\FaceSourceTrace\cache\identity`。
- 默认图库 9 人 / 45 张参考图，其中 43 张形成有效 embedding；2 张因不满足单人脸要求被明确跳过（原因写入诊断）。

### 5.4 视觉证据

查询人脸框与真实五点关键点、对齐人脸、逐参考图缩略、最佳参考图对照、Top-5 卡片；证据生成失败不影响权威检索结果。

## 6. 模块三：原始底图候选检索

### 6.1 算法全流程（冻结口径）

1. **人脸屏蔽**： Haar `haarcascade_frontalface_default` 两次尝试（1.1/5 与 1.05/3），取最大框，外扩 25%，生成椭圆掩膜；未检测到人脸时使用完整图像并记警告。
2. **全局特征**（letterbox 256×256，四通道按权重合成，分数截断 [0,1]）：

```text
global = 0.30 × HSV直方图相似度(24×16, HISTCMP_CORREL, 映射到[0,1])
       + 0.25 × 灰度缩略图余弦相似度(32×32, z-norm)
       + 0.15 × 边缘图相似度(Canny 60/160, 32×32)
       + 0.30 × 外围区域相似度(64×64 高斯模糊, exp(-MAE/45))
```

   外围通道在掩膜之外再固定挖掉中心椭圆（30% 宽 / 38% 高）——刻意构造与检测器无关的「非人脸」比较通道。

3. **粗排**：全库逐图解码并计算全局分（当前实现无持久索引，全部在内存），按全局分降序。
4. **shortlist**：`min(max(top_k×4, 20), 解码成功数)`；默认 Top-5 时复核 20 张。
5. **局部复核**：对查询图与候选图分别 `SIFT(nfeatures=2500)`、`BFMatcher(L2, k=2)`、Lowe 比率 0.75：
   - 有效匹配 < 4：退化分支 `local = min(good/40, 0.15)`；
   - 否则 `cv2.findHomography(RANSAC, 阈值 5.0)`：

```text
local = 0.6 × RANSAC内点率 + 0.4 × min(RANSAC内点数 / 40, 1)
```

6. **最终分**：`final = 0.45 × global + 0.55 × local`，**排序前不四舍五入**；输出 Top-K（默认 5）与全部中间量。

### 6.2 证据输出

屏蔽后的查询图、人脸检测框与掩膜轮廓、关键点、全部匹配连线、内点/外点区分、单应投影叠加、全局四分量分解与漏斗进度。

### 6.3 性能与限制

- 无持久索引：203 图默认库单次约 112 秒（CPU，安装版实测 112.0227 秒）；并发运行会因资源竞争恶化（论文评测记录 4 路并发下 114–375 秒）。
- 默认超时 600 秒；UI 显示真实阶段与计数。
- 无开放集拒识：库外样本仍给出「看似自信」的 Top-1（论文评测：10/10，final 0.578–0.757，均值 0.6325；库内命中区间 0.922–0.995）。

## 12. 能力边界与实测缺陷（升级要针对的靶子）

以下数字全部来自冻结 v0.4.0 的论文评测（`_paper_eval_20260919`）与已记录发现，不重跑、不修饰。

### 12.1 AIGC 跨域泛化弱（最严重）

外部集 SWAN-DF 100 张（80 REAL + 20 FAKE，四个换脸版本）：

| 分支 | ROC-AUC | 冻结阈值下 TP/FP |
|---|---:|---|
| 空间域（单独） | 0.4594 | 1 / 0 |
| 频域（单独） | 0.6525 | 0 / 0 |
| 融合 0.62/0.38（现役） | 0.4594 | 0 / 0 |
| 融合 0.5/0.5（对照） | 0.4594 | 0 / 0 |

- 20 张 FAKE 全部未检出；版本内 AUC 0.41–0.5278；事后阈值扫描（仅诊断，不代表独立性能）阈值 0.0887 时准确率 0.85、召回 0.25。
- 模块自测集 AUC 0.8430（上游技术报告），跨数据集排序能力显著退化——这是升级的第一优先级。

### 12.2 身份检索端到端成功率低

- 受控开发集 10 张：Top-1 10/10（相似度 0.5932–0.7703），但这是开发期素材，不是独立盲测。
- SWAN-DF 补充：20 张查询仅 10 张检出人脸（50%）；有效查询 Top-1 7/10；**端到端 7/20 = 35%**。60 张参考图仅 22 张有效建库。
- 聚合方式消融：受控集上「人员均值」与「最佳单图」Top-1 完全一致，仅分数尺度不同。

### 12.3 底图检索无拒识、控件集偏易

- 受控 10 查询 Top-1 10/10（final 0.9223–0.9946）；但全局分量单独使用同样 10/10（0.99+）——说明该受控集对局部复核环节没有区分度。
- 同帧对照（05 查 01 库，20 例）：Top-1 15/20；未命中样本的 Top-1 与真值来自同一视频相邻帧，分数几乎相同。
- 库外拒识（10 张 SWAN-DF 原图）：10/10 返回「自信」Top-1（final 0.578–0.757），与库内命中区间 0.92–0.99 存在经验间隔，但**没有经过验证的拒识阈值**。
- 已记录缺陷：query_001 的底图人脸框落在画面边缘（bbox 覆盖异常），掩膜未有效覆盖人脸——说明 Haar 检测在边缘/大框场景下不可靠。

### 12.4 其他既有边界

- 单图入口（JPG/PNG/WEBP，≤20 MiB），无视频、无互联网反查、无案件管理、无电子签章。
- 无上游训练仓库/训练数据；重新训练不可复现（推理可复现）。
- 随包 CUDA 未启用；GPU 推理未验收。
- 图库规模小（身份 9 人 45 张、底图 203 张），无法代表真实规模。

## 13. 升级切入点盘点（技术接口与代价）

### 13.1 方向 A：鉴伪能力升级

可动接口：

- 模型层：`packaging_v0.3\resources\deepfake_runtime\models\`（替换/新增空间、频域、融合配置）。
- 源码层：`deepfake_runtime\src\detectors\`（新增检测器）、`src\pipeline\deepfake_detection_pipeline.py`、`src\fusion\`；适配层 `modules\deepfake_detection\run_deepfake_detection.py` 负责映射与错误分类。
- 配置层：`config.json` 的 `deepfake.known_sha256`（dev 与 `config.packaged.json` 双份）与资源清单 `manifests\*.sha256.json`；测试 `tests\test_aigc_model_resource_contract.py` 会校验「不得依赖 Torch 缓存/官方权重」等合同。

约束与代价：

- 运行时是便携 CPython 3.12 + 随包 torch 2.11 CPU；引入新架构（如 CLIP/ViT 类检测器）需新增依赖并重生成受控资源清单，且必须保持离线（空 TORCH_HOME 不得触发下载）。
- 结果 schema 3.0 的 `spatial_score / frequency_score / fusion` 语义被前端、报告、论文引用；换成单模型检测器需设计映射方案（保留双分支合同或扩展 schema 并保持向后兼容）。
- 评测基线现成：SWAN-DF 100 张外部集 + 自有 145 帧验证集 + 逐版本切分，可直接量化改进。
- GPU 可选：dev venv 有 cu128 torch，但随包运行时需重建；不改包体则只能继续 CPU。

### 13.2 方向 B：寻源能力升级

- 底图索引：`pipeline.py` 全库实时扫描是冻结设计；加索引/缓存会改变耗时与并发行为，属于新版本算法变更，必须保留旧算法开关并重新做数值回归。
- 底图拒识：需要开放集校准数据（当前仅 10 例库外样本可用），输出要新增字段并明确标注「未独立验证」。
- 人脸屏蔽修复：`face_mask.py` 的 Haar 方案在画面边缘与超大框时失效；更换检测器会改变全局分与排序，需重跑受控集与同帧对照。
- 身份端到端：`extractor.py` 强制「恰好一张人脸」；放宽为「主脸选择 + 质量过滤」可提高 50% 检出率，但改变查询语义（需明确记录选择规则与风险）。
- 身份拒识：同样缺开放集验证数据；相似度分数分布需重新校准。

### 13.3 方向 C：系统整体 2.0

- 新增模块或页签需要同时改：`orchestrator.MODULE_ORDER`（代码常量）、结果契约、进度事件、`reporting\`、五页前端、测试矩阵与打包脚本。
- 兼容承诺建议：老任务可读（schema 3.0 向后兼容）、老接口保留、`mock_enabled=false` 与只读资源模型不变。

### 13.4 不可轻动的冻结合同（升级时至少要显式评估）

1. 三模块结果 schema 3.0 字段与语义；2. 进度事件 JSONL 契约；3. 任务目录结构与 artifact manifest；4. 报告三种格式与确定性模板；5. 路径安全策略；6. 安装器只读资源 + `%LOCALAPPDATA%` 数据根；7. `known_sha256` 资源校验链；8. 已发布的论文/验收引用数字（改动即为新版本，需重出对照）。
