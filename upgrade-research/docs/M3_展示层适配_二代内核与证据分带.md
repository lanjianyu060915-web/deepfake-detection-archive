# M3 展示层适配：二代内核与证据分带

日期：2026-09-20
工作副本：`D:\刑科技项目升级2.0\workspace\fsts`
基线：v0.4.0 冻结版（桌面冻结包 SHA-256 `5E8B6D04...675E3`）

## 1. 本次修复的真实缺陷

二代鉴伪内核（M3）此前只完成了配置级接入，展示层仍按 v0.4.0 的双分支固定融合结构渲染，导致三个用户可见缺陷：

1. **前端看不到核心结论**：`details` 结构从 `spatial_score/frequency_score/fusion_score` 变成 `branch/band/band_thresholds`，总览卡片与 AIGC 详情页全部显示"—"，且没有证据分带，等于把已经在外部集上有效的判别信息藏在结果文件里。
2. **证据链与报告结论误导**：`build_deepfake_explanation` 对二代结果套用旧叙述，会输出"结果未同时记录两个分支分数和可验证融合权重，无法完整复核融合公式"，并在 `label=fake` 时直接给出"疑似AI换脸"，与分带语义（证据不足/需人工复核/高风险提示）不一致。
3. **纯文本报告丢失分数**：报告里"风险分数"读取 `fusion_score`，二代结果该字段为空，真实存在的深伪风险筛查分被渲染成"未记录"。

## 2. 改动清单

### `frontend/components/evidence_dashboard.py`

- 新增 `resolve_deepfake_kernel_view(data)`：纯函数，识别二代内核结果并返回分支、分带、路由与分带边界；非二代（v0.4.0 冻结结构）或失败结果返回 `None`。分支识别顺序为 `details.branch` → `details.routed_branch` → `method.branch`。
- 新增 `_render_band_scale_chart(score, kernel)`：Vega-Lite 证据分带尺（低/中/高三段 + 本次分数游标）。
- 新增 `_render_deepfake_kernel_page(...)`：二代整图分支专属页面，展示生效分支、输入有效短边与路由阈值、风险分与分带、处置建议、校准集/验证集来源、SHA-256 溯源与局限声明。
- `_render_deepfake_page` 增加分流：整图分支走新页面，路由到冻结分支时保留原双分支视图并加一行路由说明。
- `_render_overview_cards` 的 AIGC 卡片在二代分支下改为展示"证据分带 + 深伪风险筛查分 + 输入短边"。

### `reporting/explainability.py`

- 新增 `_deepfake_kernel_view(data)` 与 `_deepfake_kernel_explanation(...)`：二代整图分支按证据分带叙述，不再输出融合公式复核警告，并显式声明"单模型输出，不产生空间域/频域加权融合分解"。
- 冻结分支叙述保持不变，仅在其 `technical` 中新增 `branch` / `branch_name` 两个键，使两个分支的 technical 结构一致。

### `reporting/report_builder.py`

- `render_text_report` 的 AIGC 段按 `technical.branch` 分流：二代分支输出生效分支、风险筛查分、证据分带、分带边界、路由依据、输入尺寸与模型哈希；旧分支输出保持不变。

### `config.json`

- 新增顶层 `upgrade` 段，记录升级轨迹、冻结基线版本、冻结包 SHA-256、已升级内核与说明。
- `product_version` 仍为 `0.4.0`：它标识的是基线契约（schema 3.0、模块协议、打包脚本断言），不是内核标识；内核切换记录在 `deepfake.kernel` 与 `upgrade.upgraded_kernels`。
